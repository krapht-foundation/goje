# M3 unit commands

This is the accepted behavior for the [M3 authored courtyard](../rfcs/0004-m3-levels-and-unit-commands.md). The reference scene and `levelcheck` use the same game-specific rule: the map needs exactly one scout and one lookout. [M2 painting and picking rules](world-view-m2.md) remain in effect.

- Each supported mouse button buffers its first valid logical position until a tick consumes it. Release and movement do not replace it. Bars are outside the input area, and focus loss clears both presses. The browser suppresses the context menu on the game canvas, not the surrounding page.
- Restart takes precedence over both edges. Otherwise, resolve the primary press using the existing paint order before interpreting the secondary press, even if the events arrived in the opposite order. A secondary press leaves selection alone. Convert its point with the tick-start camera and unproject onto elevation zero; floor both coordinates to select a ground cell.
- The example commands the scout. Walls, the board boundary, and the stationary lookout block movement. Use the first shortest cardinal route in neighbor order `+X`, `+Y`, `−X`, `−Y`, excluding the start and including the destination. A blocked, unreachable, or out-of-bounds goal leaves the current order intact. Without a selection, no order is issued.
- A valid order replaces the destination. If movement is already between centers, keep the current edge and plan from its endpoint. A destination equal to that endpoint clears the rest of the route; a destination equal to the current center while stationary is a no-op. Move at a fixed tick speed, clamp each step to the next tile center, and clear the destination marker on arrival. Restart restores the authored spawns, starting camera, and empty selection and route.
- Search only on a command and reuse bounded scratch storage. Rebuild paint order when ground anchors move. Camera changes, resize, and draws do not alter movement or navigation state.
